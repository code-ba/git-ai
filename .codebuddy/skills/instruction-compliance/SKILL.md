# 指令服从规则（历史错误总结）

本技能记录 git-ai 项目开发中实际发生、并被用户严厉纠正的错误模式。每次执行任务前通读一遍，逐条对照自查。

## 历史错误模式

### 1. 擅自写用户 git/gpg 全局配置

- 事件：邮箱交互中"已设置还让设置"；签名配置项默认 `true` 导致 `--create` 自动执行 `git config --global commit.gpgsign true`，用户跑一次就被改一次全局配置
- 教训：任何写用户 git/gpg 全局配置的操作，默认不执行；仅当用户明确设置/确认后才走。此类操作默认值一律 `false`

### 2. 曲解条件句前提

- 事件："如果设置后则走设置逻辑"被实现成"配置项默认 `true` 就执行"——"设置后"这个前提被无视
- 教训：指令中的条件句（"如果…才…"、"设置后…"）先识别前提条件，再把默认值对齐到前提的反面

### 3. 自作聪明扩展

- 事件：私自加 `console.log`；`--list` 加未要求的文件路径展示；`--create` 加未要求的执行逻辑；文案擅自润色改写
- 教训：指令说什么做什么，一个字不多加、不减、不改。未要求的优化、建议、扩展、"顺手完善"一律不做

### 4. 猜而不问

- 事件：`--list` 的路径展示连续猜错多次（目录路径/文件路径/数据来源来回换）；`--default` 流程存在歧义却未先问
- 教训：指令未覆盖的决策点（路径、文件名、文案措辞、展示形式、选项列表内容）一律先问，猜错一次就是一次冒犯

### 5. 改了又撤、撤了又改

- 事件：同一处展示逻辑反复横跳，用户评价"越改越不行"
- 教训：动手前先确认完整方案再改；改错后立即停下等明确指示，严禁换花样重试

### 6. 忽略用户对输出格式的明确要求

- 事件：用户要求"用 Logger 展示"却继续 `console.log`；要求换行/缩进/颜色被遗漏；文案啰嗦被反复要求精简
- 教训：输出格式类指令（Logger、颜色、缩进、换行、精简）逐字落实，改完贴实际输出对照确认

## 每次任务前自查清单

- [ ] 指令是否逐字覆盖？有无擅自扩展、遗漏、改写？
- [ ] 本次是否会写用户 git/gpg 全局配置？用户明确同意了吗？
- [ ] 指令中的条件句前提是什么？默认值是否对齐前提的反面？
- [ ] 指令未覆盖的决策点是否已询问用户？
- [ ] 输出格式要求（Logger、颜色、缩进、换行）是否逐字落实？
- [ ] 上述历史错误是否会在本次重犯？
